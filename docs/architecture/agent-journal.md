# journal の仕様

**読み手:** journal の内容と生成器を保守する開発者。
設計と変更の判断中に読む。

## 目的

journal は、複数のプロジェクトで AI エージェントと行った作業から、技術的な知見や気づきを集積する。
読者が元の会話を読み直さなくても、何が分かり、その根拠と適用条件は何かを理解できる記録を作る。
日付は収集の区切り、プロジェクトと session は出典であり、記事の主題にはしない。
業務仕様の保管、日々の活動報告、エージェント向けの project memory は目的に含めない。

## 採用する内容

技術的な問題の切り分け、実装や設計の方法、ツールの挙動、試した方法の成否など、作業を通して得られた具体的な理解を一件の知見とする。
既知の理解を覆した観測、失敗して初めて分かった制約、未検証だが根拠のある気づきも対象とする。
すべてを汎用的な教訓に変換せず、結論を支える実際の条件と失敗を残す。
一方、変更、テスト、commit を行ったという事実だけでは知見にしない。
通常のログイン、作業再開、進捗や残件、業務上の仕様決定、費用と request 数の一覧は採用しない。
同じ技術的な論点はプロジェクトをまたいでまとめるが、成立条件の異なる事例を同じ結論に丸めない。

記事には、具体的な発見を示す題名、分かったこと、その説明、適用条件や用途、注意点と未確認事項を含める。
説明では、問題と制約、試した方法、観測、判断のつながりを示す。
一般論を付け足したり、根拠にない因果や再現性を補ったりしない。
仮説は仮説として明記し、成功の報告だけから独立に検証済みの事実へ格上げしない。

## 入力と日付の境界

入力は、OMP が保存する親 session の原記録であり、既存 journal を再要約しない。
隣接する subagent の記録は親と重複するため対象外とする。
対象日の 06:00 以上、翌日 06:00 未満に入る entry を収集する。
開始前の説明を失わないよう、同じ session の直前の可視記録を上限内で背景として添え、収まらなければ古い記録から除く。
長い背景を切り詰める場合も原文の連続した末尾だけを使い、省略を示す文字を引用可能な本文へ追加しない。
背景だけの session は対象にせず、背景の引用しか持たない知見も採用しない。
日付の境界をまたいだ作業を、その日の entry だけで完結した出来事として解釈しない。

model へ渡すのは利用者の発言、エージェントの可視の応答、tool の名前と実行意図である。
thinking、tool の引数と生の実行結果、注入された記憶、自動通知は渡さない。
記憶の収穫が読む利用者発言の原文と時間窓は変更しない。
長い可視記録は入力を分割して処理し、従来の先頭だけの切り詰めで結論や制約を失わない。
背景は上限のある補助情報であり、過去の session 全体や別の日の知識を網羅するものではない。

tool の生の結果を送らないため、エージェントが報告した観測を実行結果そのものと同一視しない。
出典に支持された記事も、その会話に何が記録されているかを示すものであり、この生成器が実験を再実行した証明ではない。
根拠が報告にとどまる場合や、原因がまだ確定していない場合は、その限界を本文に残す。

## 出典と生成

生成は、知見候補の抽出と、技術的なテーマごとの編集に分ける。
抽出では各入力範囲からゼロ件以上の候補を取り出し、編集では全 session の候補を読み、重複をまとめる。
各候補は、元の session の完全な ID、entry の ID、可視本文からの正確な引用を持つ。
entry に ID がない旧記録では、原 file の行番号であることを示す locator を使う。
編集で、渡されていない出典や引用を追加してはならない。
入力と候補はすべて分析対象の data として扱い、その中の指示を生成器への指示として実行しない。

記録に支持される状態を `supported` とする記事は、同じ状態の候補が持つ引用だけを根拠にできるものとし、仮説の根拠を使う記事を自動的に格上げしない。
プログラムは両段階で応答の構造、出典の存在、引用の一致、対象日内の根拠を検査する。
知見候補がないことは正常であり、件数を満たすために記事を作らない。
大きな入力と候補は、背景、出典情報、JSON の表記を含む長さが上限内に収まるよう分割して処理する。
対象日の本文は分割しても欠落させず、出典情報だけで上限を使い切る場合や編集結果を上限内へ縮約できない場合は明示的に失敗する。
不正な応答を活動報告へ置き換える fallback は持たない。

program による引用検査は、本文の技術的な正しさや知見としての価値を保証しない。
生成方針を変えるときは、原 session を用いて実際に記事を生成し、技術的な発見、根拠、適用条件が本文から読み取れることを確認する。
活動だけの記録から架空の知見を作らないこと、根拠の弱い気づきを検証済みの結論にしないことも確認する。
model の出力を固定文字列へ合わせる検査を、この内容確認の代わりにしない。

## 出力と失敗

出力は日付と機械ごとの Markdown とし、その中に技術的なテーマごとの記事を並べる。
記事には根拠となる引用と出典を添え、完全な session ID から元の会話を開けるようにする。
引用は Markdown や HTML として解釈されない code block に置き、引用内の記法も原文として読めるようにする。
プロジェクトごとの活動表、依頼・決定・変更・未決事項の四分類、全 commit と session の一覧は出力しない。
活動のある日に知見を抽出できなければ、その旨を記した正常な文書を作り、未生成と区別する。
活動自体がない日は従来どおり file を作らない。

すべての記事の生成と検査が終わるまで、既存の文書を置き換えない。
model の失敗、構造や引用の不正では、その日を非成功として報告し、既存の文書と公開先を変更しない。
一つの日の model や file 操作の失敗は、その日と原因を報告してほかの日の処理を続け、全体を非成功として返す。
排他、期限、原子的な置換、commit と公開の再開は既存の job と Git の契約を使う。
操作は [journal の運用](../operations/agent-journal.md)、job の寿命は [AI tooling](ai-tooling.md#非対話-job-の寿命)に従う。

## 旧記録からの切替

新しい出力は形式の marker を持ち、旧来の活動報告と区別する。
公開済みの旧記録は通常実行で書き換えず、新仕様を満たした記録とも扱わない。
未公開の旧記録を新しい生成器がそのまま公開することは、記録の機械名によらず拒否し、明示した日付のプレビューと再生成を要求する。
過去分を作り直す場合も原 session を入力とし、旧記録を知見の根拠として再利用しない。
既存記録の一括削除、一括上書き、履歴の書き換えは自動移行に含めない。

`--preview --date` は通常と同じ生成と検査を行い、完成した Markdown だけを標準出力へ返す。
日誌 repository の参照、同期、書込み、commit、push は行わず、失敗時は途中の記事を標準出力へ返さない。
プレビューの成功は内容の承認や公開の許可を意味しない。
