# 0017. 文書を学習・手順・参照・説明に分け、読み手を定める

## 状態

Accepted

## 背景

[ADR 0016](0016-documentation-model.md) は文書を 手順、構造、索引、判断 の四つに分けた。この四つは読み手のニーズで分かれておらず、「構造」は読み手が理解したい説明、「判断」は決定の記録であって文書の種別ではない。学習にあたる区分が無く、どの文書も想定する読み手を書いていない。

読み手のニーズは、学びたい、やり遂げたい、調べたい、理解したい、で質的に異なる。作業中に参照する記述と、作業を離れて理解する記述を混ぜると、どちらも役に立たない。読み手を定めずに書いた文書は種別が滲む。

## 決定

文書を学習、手順、参照、説明の四種別に分ける。決定の記録はこの四種別と直交する別の軸であり、ADR が持つ。

| 種別 | ディレクトリ | 読み手の状態 | 読み手 |
|---|---|---|---|
| 学習 | `learning/` | 学習中 | この構成を初めて触り、全体像を掴みたい人 |
| 手順 | `operations/` | 作業中 | 目的の作業をやり遂げたい運用者 |
| 参照 | `reference/` | 作業中 | 正本の場所と現在値の取り方を調べたい人 |
| 説明 | `architecture/` | 学習中 | 責務の境界と要素の関係を理解したい人 |

各文書は冒頭に読み手と、その読み手が作業中か学習中かを書く。参照の文書は、リンクを辿らなくてもその場で作業を完結できる形にする。

現時点で学習にあたる文書を持たない。持たない種別のディレクトリは作らない。`getting-started.md` は新規ホストを構築しきることが目的であり、手順に属する。

決定の記録は `adr/` に置く。状態が `Accepted` の ADR を覆すときは本文を書き換えず、新しい ADR で置換し、旧 ADR の状態を `Superseded by` に変える。

ADR 0016 が定めた次の三つは維持する。環境の観測と実装計画を追跡しないこと、不変記録を後から訂正しないこと、索引が宣言の値を転記せず場所だけを指すことである。

## 検討した代替案

ADR 0016 の四分類に学習を足す案。「構造」と「説明」、「判断」と決定の記録の混同が残り、読み手のニーズで分かれないため不採用。

ADR 0016 の本文を書き換える案。決定を覆すときに古い記録を書き換えると、当時の判断が失われ、同じ議論を繰り返す。置換で残す。

## 影響

`docs/README.md` の分類が四種別になり、各文書が読み手を明示する。ディレクトリ名は `architecture/` を維持する。名前を `explanation/` へ変えても読み手の理解は増えず、既存の参照をすべて書き換える費用だけが生じる。

学習の文書が必要になった時点で `learning/` を作る。それまでは空のディレクトリを置かない。
