# ツール構成監査（2026-07-29）

最優先は package の削減ではなく、agentgateway の session 増殖を止めることである。`sessionTtl = "4h"` を上流既定の 30 分へ戻す。続いて Playwright と Codex の接続経路を target 別、AI CLI 別に確定し、既存接続を維持したまま opt-in endpoint へ移す。agentgateway 1.4.0 への更新、loopback bind、検査の自動化もこの順で行う。

## 範囲

dotfiles の Nix 宣言、`/home/nixos/projects` と `/home/nixos/workspace` の利用箇所、稼働中 service を突き合わせた。project と workspace は依存物、cache、生成物を除いて検索した。shell history と editor telemetry は対象外である。

## gateway

`modules/mcp/gateway.nix:20-39` は 10 target を一つの backend group に束ね、session TTL を 4 時間に固定する。agentgateway は session ごとに全 stdio target を起動するため、Playwright を呼ばない session でも Chromium を含む一式が増える。

監査時点の service は次の状態だった。

```text
$ systemctl status agentgateway.service
Active: active (running) since 2026-07-29 19:51:22 UTC
Tasks: 2051
Memory: 7.7G

$ systemctl show agentgateway.service \
    -p TasksCurrent -p MemoryCurrent -p LimitNOFILE
TasksCurrent=2051
MemoryCurrent=8300441600
LimitNOFILE=1048576
```

同じ起動期間の journal には `initialize=25`、session の `DELETE=3` があり、未削除は 22 session だった。保持されていた約 10 時間分の `tools/call` は次の通り。

| target | call |
|---|---:|
| searxng | 495 |
| crawl4ai | 223 |
| memory | 95 |
| github-account-1 | 58 |
| github-account-2 | 10 |
| probe | 9 |
| context7 | 7 |
| playwright | 1 |
| codex | 0 |
| github-account-3 | 0 |

10 時間の観測だけで Codex や 3 番目の GitHub account を廃止する根拠にはならない。一方、Playwright は 1 call に対して session ごとに Chromium を起動しており、常設 group から外す根拠になる。

上流は、client が session を削除しない場合に stdio process が残るため idle reaper を導入し、既定 TTL を 30 分としている。[agentgateway #1569](https://github.com/agentgateway/agentgateway/pull/1569) 現行設定はこの既定値を 4 時間へ延ばしている。

### 訂正 (2026-07-31)

この節の計測と読み取りに三つの誤りがあった。

`LimitNOFILE=1048576` は hard 値だけを見ており、実効値である `LimitNOFILESoft` を取得していなかった。soft は systemd 既定の 1024 で、これが実際に到達する上限である。journal には `Too many open files (os error 24)` が記録され、新しい initialize が HTTP 500 で失敗していた。`systemctl show` に `-p LimitNOFILESoft` を含めていれば当日に判明した。

`initialize=25` から `DELETE=3` を引いて未削除 22 session としたが、この差は reaper による削除を含まないため active session の正確な gauge ではない。gateway は当時 active session の gauge を持たず、この数は上限の推定値として扱うべきだった。

`agentgateway 1.4.0 へ更新する` を改善項目に挙げているが、1.4.0 の downstream SSE builder も keepalive に `None` を渡すため、version 更新は session lifecycle の修正にならない。endpoint 分離の前提としては必要だが、この蓄積の解ではない。判断は [ADR 0015](../adr/0015-mcp-session-lifecycle.md) に記録した。

## 待受境界

```text
$ ss -ltnp '( sport = :8765 )'
LISTEN 0 128 *:8765 *:*

$ systemctl is-enabled firewall.service
masked
```

`modules/options.nix:26-30` は port を loopback と説明するが、実際は wildcard bind である。NixOS-WSL は WSL 上で `firewall.service` を明示的に無効化するため、NixOS firewall を境界にはできない。[NixOS-WSL source](https://github.com/nix-community/NixOS-WSL/blob/add6b01c7ca72240046b5d541a74845423f1ee35/modules/systemd/default.nix#L14-L20)

agentgateway 1.3.1 の `LocalBind` schema は `port`、`listeners`、`tunnelProtocol` だけを持ち、listen address を指定できない。[v1.3.1 schema](https://github.com/agentgateway/agentgateway/blob/v1.3.1/schema/config.json) 1.4.0 の `gateways` と `LocalBind` にも address field はない。[v1.4.0 schema](https://github.com/agentgateway/agentgateway/blob/v1.4.0/schema/config.json)

## 改善

### 1. session TTL を 30 分へ戻す

`modules/mcp/gateway.nix:22` を上流既定の `30m` に変更する。現在の `LimitNOFILE=1048576` は十分に高いため、file descriptor 上限は変更しない。

適用後は複数の AI CLI を接続したまま 60 分観測し、30 分を超えて idle な session の子 process が消えること、`TasksCurrent` と `MemoryCurrent` が単調増加しないことを確認する。doctor には `TasksCurrent`、`MemoryCurrent`、session 数を追加し、正常時の実測から上限を固定する。

### 2. Playwright と Codex の opt-in endpoint を分ける

`playwright` と `codex` の package は維持する。まず 4 AI CLI について、default gateway、project-local MCP、Claude plugin のどの target を登録し、どの repository が許可しているかを target 名単位で一覧にする。現時点の 13 config は gateway の `playwright` と Claude plugin の別 target を混在させており、そのまま移行対象には使えない。

target と client の対応を確定した後、Nix 管理の opt-in endpoint または project-local wrapper を追加し、既存の default target と並行稼働させる。利用 repository を一つずつ移し、4 AI CLI の initialize、tool list、代表 call を確認する。default target への接続がなくなってから default group から外し、無関係な session で Chromium と Codex process を起動しない構成へ揃える。

### 3. agentgateway 1.4.0 へ更新する

現行 pin は `pkgs/agentgateway/default.nix:8-22` の 1.3.1 である。監査時点の最新安定版 1.4.0 は MCP 2026-07-28 対応と、新しい `gateways` 構成を含む。[v1.4.0 release](https://github.com/agentgateway/agentgateway/releases/tag/v1.4.0)

1.3.1 以前には stateful MCP session が route を跨いで authorization policy を取り違える問題があり、1.4.0 で修正された。現行は単一 route なので advisory にある複数 route の成立条件を満たさないが、認証追加や route 分割より先に更新する。[GHSA-mvgg-jvj2-4frq](https://github.com/agentgateway/agentgateway/security/advisories/GHSA-mvgg-jvj2-4frq)

更新時は `pkgs/agentgateway/mcp-session-recovery.patch` の要否を上流差分から再判定し、4 AI CLI の initialize、tool list、代表 call、session reap を実測する。`binds` は deprecated なので `gateways` へ同時に移す。

### 4. loopback bind を実装する

1.4.0 へ更新した source に listen address field を追加し、`127.0.0.1:8765` だけを bind する patch を upstream へ提案する。全 AI CLI の接続先も `localhost` から `127.0.0.1` へ揃える。ローカル patch を先行させる場合も schema、config 変換、socket bind、client URL、test を一単位で変更する。

doctor は `ss` の実値を検査し、`127.0.0.1:8765` 以外での待受を失敗にする。併せて `modules/options.nix:29` の説明を実装と一致させる。API key 認証は loopback 化の代替ではなく、loopback 外へ公開する要件が生じたときに追加する。

### 5. 検査を宣言へ寄せる

shfmt は user package にあるが、flake check から呼ばれていない。ShellCheck と同じ 15 file を `shfmt -d` に渡すと差分が出る。既存の `.editorconfig` を基準に一度整形し、`flake check` に shfmt を追加する。上流も CI では `shfmt -d .` を案内している。[shfmt manual](https://github.com/mvdan/sh/blob/v3.12.0/cmd/shfmt/shfmt.1.scd)

文書リンクは今回、lychee の offline check で 256 link、0 error を確認した。これを `nix flake check` に固定し、README や docs の移動を CI で検出する。lychee は Nix package と `testers.lycheeLinkCheck` を提供している。[lychee README](https://github.com/lycheeverse/lychee/blob/master/README.md)

### 6. global package を一件だけ削除候補にする

`modules/user/default.nix:51` の `just` を global package の削除候補にする。確認した 5 repository はすべて project-local devenv が `pkgs.just` を供給するため、`direnv` が有効な checkout では同じ command を使える。just 自体と各 project の宣言は残す。

global `just` の利用履歴は取得していないため、この監査だけでは削除を確定しない。5 repository の task と checkout 外で使う運用が project-local `just` だけで成立することを確認してから削除する。

Vim、nixd、shfmt、global nixfmt は shell history や editor telemetry を監査していないため、現時点では削除しない。wget は一つの Maven wrapper、Python と uv は複数の project で実行経路がある。devenv、nvd、curl、jq、yq、GitHub CLI も現行運用が直接依存している。

### 7. inventory と pin 更新を command 化する

評価済み NixOS config と flake outputs から system package、user package、devShell、AI CLI、agent、skill、MCP target、container を出す `dotfiles-inventory --format human|json` を追加する。文書へ version を転記せず、現行 roster を一つの command で確認できるようにする。

`scripts/pin-hash.sh:23-41` は ambient な `nix`、`docker`、`jq` を探して実行する。これを `dotfiles-pin-hash` の `writeShellApplication` へ移し、runtime input と flake package を宣言する。以後、保守 command は生成 command だけを入口にする。
