# ADR 0001: architecture-standard を設計判断の基準として採用する

**読み手:** この repository の設計判断が何を根拠にしているかを確かめる人。

## Status

Accepted

## Context

この repository は個人の作業環境を宣言的に管理し、unit 単位で責務を分けてきた。判断の根拠は各 unit の実装と `docs/architecture/` の説明に置かれ、判断の基準そのものは持たなかった。そのため、境界の切り方、正本の置き場、検証の粒度という繰り返し現れる判断が、その都度の裁量で決まる。同じ論点が再燃しても、どちらが基準に合うかを客観的に判定できない。

候補は三つあった。基準を持たず個別に判断する現状の継続、この repository 内へ独自の原則集を書く形、外部の標準を基準として参照する形である。現状の継続は判定の枠を持たないため、逸脱と裁量を区別できない。独自の原則集は、原則の保守と、原則と実装の同期という二つの負担を、この repository の目的の外へ足す。

`github:YukiIto1999/architecture-standard` は principles、concerns、structure、tools、process の五領域を持ち、領域間の参照を具象から抽象への一方向に固定し、遵守判定の枠と severity を定義する。標準は本文の転写を禁じ、対象 project へは参照先の宣言だけを置く形式を定める。

## Decision

設計、実装、レビュー、監査の判断基準として architecture-standard を採用する。標準本文はこの repository へ転写せず、参照先として宣言する。標準が沈黙する目的については、principles の要求と禁止事項に照らして project 自身が決定し、単一採用としてこの記録の系列へ残す。

## Consequences

判断の根拠が、標準本文の該当規律と、この repository の決定の記録の二つに分かれる。標準の改訂によって既存の実装が違反になった場合は、標準の migration の手順に従って現行の標準へ寄せる。

標準の沈黙と逸脱には記録が必須になるため、記録の置き場と標準本文の参照方法を、それぞれ別の記録で決める。
