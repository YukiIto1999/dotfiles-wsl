# ADR 0003: 設計判断の記録を docs/adr に置く

**読み手:** 構造に影響する判断の文脈と代替案をどこで読むかを確かめる人。

## Status

Accepted

## Context

標準は、構造に影響する決定を文脈、決定、帰結、代替案とともに残すことを要求し、その根拠として commit log は直接の目的を示すが判断に至った文脈、代替案、帰結までは保持しないと述べる（標準 `principles/documentation/decision-records.md`）。

この repository の文書は手順、説明、参照の三種で、ディレクトリと種別が一対一に対応する（`docs/README.md`）。決定を持つ種別はない。さらに `docs/architecture/cohesion.md` の「設計文書の規律」は、設計書から過去の作業履歴と旧構成の差分経過を除き、変更の経緯と理由を commit message と PR 説明へ完結させると定めていた。結果として、構造に影響する判断の文脈と代替案の正本が存在せず、却下した判断の一部は `docs/architecture/skills.md` の節、廃止した経路の一部は検査内の文字列として散在していた。

候補は三つあった。commit と PR へ完結させる現状の継続、`docs/architecture/` へ経緯を書き足す形、決定の記録の種別を新設する形である。一つ目は標準の要求を満たさず、逸脱として記録する場合もその置き場自体がない。二つ目は同じ `cohesion.md` が設計書から履歴と経緯を除くと定める規律と衝突し、説明の文書に説明以外の種別を混ぜる。

## Decision

構造に影響する決定を `docs/adr/` へ置く。ファイル名は 4 桁の連番と英語 kebab の slug とし、一つの判断に一つの記録を対応させる。節構成は Status、Context、Decision、Consequences とし、比較した候補と採らなかった理由を Context に含める。覆すときは古い記録を消さず、置換済みとして印を付ける。

変更の直接の目的は commit message と PR 説明が持ち、構造に影響する判断の文脈、代替案、帰結はこの記録が持つ。`cohesion.md` の「設計文書の規律」はこの分担に合わせて改める。

境界は読み手の必要で決める。ある時点の判断を後から再検討したい読み手が読むものは決定の記録に置き、現在の構造がなぜそうなっているかを理解したい読み手が読むものは説明文書に置く。同じ代替案に触れていても、この二つは別の種別である。`docs/architecture/skills.md` が持つ Skill portfolio の採否は後者に属する。

## Consequences

判断の文脈の正本が一箇所になる。`docs/` の種別は四つになり、索引はこのディレクトリを種別として指す。記録を個別に列挙する索引は作らず、ディレクトリの内容を正本とする。

`checks/checks/documentation.nix` の `docs-reader` は手順、説明、参照の三種を対象にするため、この種別は読み手の行を機械検査されない。記録の冒頭に読み手を書く規律は `docs/README.md` に従って維持する。
