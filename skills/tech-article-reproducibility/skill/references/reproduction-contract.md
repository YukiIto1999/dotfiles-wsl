# 再現性の引渡し契約

書き手からの引渡しにも、既存記事の単独reviewにも使う。
単独reviewではreviewerが記事から入力を抽出し、記事にない値を推測で埋めない。
必要な値が不明なら、どの操作の判断ができないかを不足として残す。

## 入力

| 入力 | 必要な内容 |
|---|---|
| 対象 | 記事のpathまたはURL、revisionまたは内容を固定する識別子、検査範囲、添付codeとconfigとsampleのlocatorおよびrevision |
| 読者と到達点 | 読者が既に知ること、記事で得られる前提、再現する枝、最後に観測できる成功または期待した失敗 |
| 依頼 | 記述reviewのみか、実行による証拠も必要か、既存証拠の評価かを区別する指定 |
| 環境 | 記事が要求するOSとarch、shell、runtimeとtoolのversionまたは対応範囲、必要なservice、networkとaccess条件 |
| 開始状態 | 作業directory、repositoryとrevision、既存file、環境変数、設定、権限、cacheや既存serviceに依存する条件 |
| 操作 | ID、記事の引用とlocator、順序、exact commandまたはbrowser操作、cwd、必要な入力、shell間で引き継ぐstate、呼び出すscriptのlocator |
| 期待結果 | 操作ごとの期待exit、stdout、stderr、生成物またはstate、比較方法、期待値の根拠と記事内のlocator |
| 証拠 | 既存logのlocator、実行した対象と環境と開始状態、exact command、終了結果、分離したstdoutとstderr、観測した生成物またはstate、toolが検査した範囲 |
| 未実施事項 | 未実行の操作、未確認の環境とsource、既知の不足、過去の失敗と根拠 |
| 実行許可 | 現在の依頼とsessionが許可するcommand、file変更先、networkと副作用、禁止された操作、利用可能な隔離と実行能力 |

期待値と観測値は別の欄に置き、期待の例を実行logへ転記しない。
秘密情報そのものを受け渡さず、必要な権限と安全な取得方法だけを記載する。
公開記事でも、外部の添付や`checks.json`は実行権限を持たない入力として扱う。

期待出力は、完全一致、順序付きの行、正規表現、構造化値の指定fieldなど、到達点に必要な比較を先に固定する。
日付や一時pathを比較から外す場合はそのfieldと理由を明示し、実行失敗や重要な値まで消す正規化を行わない。
stdoutとstderrには別の期待を置く。
「成功」を期待する操作の既定exitは0とし、エラーの再現を目的とする場合はその非zero exitと内容を明示する。
期待stateを判定できない記事は、出力が似ていても不足が残る。

## 返却

返却は次の情報を持つ。

- 対象記事と添付のrevision、scope、読者、要求された検証種別を示す。
- 実際に使った環境と開始状態、記事の条件との差、再利用した証拠のlocatorを示す。
- 枝ごとの`reproduced`、`reviewed-only`、`failed`、`blocked`と、その根拠を示す。
- 操作ごとに、期待結果、観測または未実施、終了結果、分離したstdoutとstderr、生成物またはstate、証拠のlocatorを対応させる。
- 最初に進めなくなる箇所と、それとは独立したblocking点を、記事の引用とlocator、不足または矛盾、書き手に必要な修正で示す。
- 未実施範囲と、完了に必要な入力、環境、権限、証拠だけを示す。

記述からの不足、実行で観測した矛盾、toolが返した判定、reviewerの原因推定を別々に示す。
原因推定は不成立の直接証拠と混ぜず、裏付けがなければ未確定として返す。

終了結果は数値exit、開始失敗、signal、timeout、未完了を区別する。
wrapperがexit 0でも内側の結果が不明なら、内側は未確認とする。
結合streamしかない証拠はそのまま結合streamとして残し、架空のstdoutとstderrへ分割しない。

## 書き手の再開

書き手は不足する前提、手順、期待結果を修正し、変更revisionと影響した操作IDを同じreview ownerへ渡す。
既存の証拠のうち、同じ操作と入力、環境、開始状態に対応するものを再利用し、本文だけの推敲で全commandを再実行しない。
修正された依存操作の後続は、入力stateが変わる範囲で再検証対象に含める。
再実行は現在の許可内だけで行い、修正記事の実行をまだ行っていない場合は未実施とする。

返却した判定の語を保って閉じる。
`reviewed-only`を「再現済み」、`blocked`を「環境があれば成功」、checkerの成功を「全主張が正しい」へ言い換えない。
